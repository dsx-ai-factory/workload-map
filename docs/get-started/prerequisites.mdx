This page lists what you need before you install the Go library, the `kli` CLI, or the operator. For what each component does, refer to the [Components](../about/architecture-overview.mdx#components) table in the Architecture Overview. You do not need all three, so read only the section for the component that you plan to install.

## Go Library

- Go 1.27.3 or later. This is the `go` version in the `go.mod` file of the repository.
- No cluster is required.

## kli CLI

The requirements depend on how you install `kli`.

| Installation method | What you need |
| --- | --- |
| Homebrew | Homebrew on macOS or Linux. |
| Prebuilt archive | Nothing else. Archives are published for Linux and macOS on amd64 and arm64. |
| Build from a clone | Go 1.27.3 or later, `make`, and a clone of the repository. |

To run `kli` against a cluster, you also need a kubeconfig with read access to the workloads that you want to see.

## Operator

- A Kubernetes cluster. Kubernetes 1.34 is the version used in end-to-end testing.
- Helm. Helm 3.16 is the version used in end-to-end testing.
- Permission to create a CustomResourceDefinition, a ClusterRole and its binding, and webhook configurations.
- Pull access to two images: the operator image, `ghcr.io/dsx-ai-factory/workload-map/karta-operator`, and the CRD upgrader image, `registry.k8s.io/kubectl`. For a private registry, set `imagePullSecrets` in the chart values.
- A network path from the Kubernetes API server to the operator webhook service.
- cert-manager, only if you supply the webhook certificate yourself with cert-manager. The default certificate mode does not need it. For more information, refer to [Webhook Certificates](../guides/operator/configure-webhook-certificates.mdx).
