This page explains how to install each Workload Map component: the `kli` CLI, the Go library, the Karta Operator, and the DSX Workload Exporter. The components are independent, so you can install any one of them without the others. Before you install a component, check its requirements in [Prerequisites](prerequisites.mdx).

## Install the kli CLI

### Install with Homebrew

On macOS or Linux, add the repository as a Homebrew tap by its URL, then install `kli` by its full name:

```bash
brew tap dsx-ai-factory/kli https://github.com/dsx-ai-factory/workload-map
brew install dsx-ai-factory/kli/kli
```

The URL is required because the short form of `brew tap` resolves only repositories named `homebrew-<name>`. To install a later release, run `brew upgrade kli`.

### Install a prebuilt archive

1. Download the archive for your platform from the [releases page](https://github.com/dsx-ai-factory/workload-map/releases). Each release publishes archives for Linux and macOS on amd64 and arm64.
2. Check the archive against the `checksums.txt` file in the same release.
3. Put the `kli` executable on your `PATH`.

### Verify the installation

```bash
kli --version
```

The command prints the release version. For shell completion and for installing from a clone of the repository, refer to the [CLI Guide](../inspect-workloads/use-the-cli.mdx).

<Note title="go install is not supported">
Do not install `kli` with `go install`. The CLI module builds against the library in the same commit through a `replace` directive, which `go install` refuses.
</Note>

## Install the Go Library

Add the library to your Go module:

```bash
go get github.com/dsx-ai-factory/workload-map/karta/sdk@latest
```

<Note title="Moved module path">
Releases up to v0.2.x published the library as `github.com/dsx-ai-factory/workload-map`. To move to the new path, require `github.com/dsx-ai-factory/workload-map/karta/sdk` and change your imports from `github.com/dsx-ai-factory/workload-map/pkg/...` to `github.com/dsx-ai-factory/workload-map/karta/sdk/pkg/...`.
</Note>

## Install the Karta Operator

1. Install the Karta Operator and the `Karta` CRD with the Helm chart:

   ```bash
   helm upgrade --install karta oci://ghcr.io/dsx-ai-factory/workload-map/karta \
     --version <version> \
     -n karta-system --create-namespace
   ```

   Replace `<version>` with a chart version from the [releases page](https://github.com/dsx-ai-factory/workload-map/releases).

2. To verify the installation, check that the Karta Operator pod is running and that the `Karta` CRD exists:

   ```bash
   kubectl -n karta-system get pods
   kubectl get crd kartas.run.ai
   ```

To change the certificate mode or run the Karta Operator in FIPS mode, refer to [Webhook Certificates](../configure-the-karta-operator/configure-webhook-certificates.mdx) and [FIPS 140-3](../configure-the-karta-operator/run-in-fips-mode.mdx). To change other chart values, refer to [Helm Chart Values](../reference/helm-chart-values.mdx).

## Install the DSX Workload Exporter

The exporter is part of the Karta Helm chart, and it runs without the Karta Operator. Helm and `kubectl` must point to the cluster where you want to install it.

Set `VERSION` to a published chart version that includes the exporter. Chart version 0.3.0 predates it. The chart supplies the matching exporter image, and no values file is required.

```bash
VERSION=CHART_VERSION

helm upgrade --install dsx-workload \
  oci://ghcr.io/dsx-ai-factory/workload-map/karta \
  --version "$VERSION" \
  --namespace karta-system --create-namespace \
  --set operator.enabled=false \
  --set webhook.enabled=false \
  --set exporter.enabled=true \
  --wait --timeout 5m
```

Helm creates the installation namespace. By default, the exporter observes all namespaces except `kube-system`, `kube-public`, and `kube-node-lease`. Both the bundled definitions and the definitions in the cluster are enabled. The chart installs the `Karta` CRD and maintains it through its upgrade hook. Built-in workload kinds do not require `Karta` objects, and a definition in the cluster overrides a bundled one.

If Karta is already installed, use a separate namespace and release. To leave its shared CRD unchanged, add both `--skip-crds` and `--set crdUpgrader.enabled=false`.

To verify the installation, forward the port of the exporter service:

```bash
kubectl -n karta-system port-forward service/dsx-workload-exporter 8080:8080
```

In another terminal, check the readiness endpoint and the metrics:

```bash
curl -fv http://127.0.0.1:8080/readyz
curl -fsS http://127.0.0.1:8080/metrics | grep '^dsx_'
```

Readiness returns HTTP 200 with an empty body when the definition inventory and the required watches are healthy. Inspect `dsx_exporter_observation_valid` for collection and workload errors. A successful scrape alone does not establish that the observations are valid.

For namespace selection, definition sources, labels, worker counts, resources, permissions, and Prometheus Operator discovery, refer to the [exporter configuration reference](https://github.com/dsx-ai-factory/workload-map/blob/main/docs/dsx-workload-exporter/configuration.md). For the metric names and labels, refer to the [metric reference](https://github.com/dsx-ai-factory/workload-map/blob/main/docs/keps/0001-metrics-exporter/README.md#metrics).

To uninstall the exporter, run the following command. The namespace and the shared `Karta` CRD remain, because other installations may use them.

```bash
helm uninstall dsx-workload --namespace karta-system
```
