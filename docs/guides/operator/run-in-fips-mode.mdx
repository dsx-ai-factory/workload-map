The Workload Map operator image is built with the native [FIPS 140-3 support](https://go.dev/doc/security/fips140) of Go (`GOFIPS140=v1.0.0`). All `crypto/*` operations are served by the CMVP-validated Go Cryptographic Module.

The operator uses a single image. The FIPS module is always linked in, and the `global.fipsMode` chart value controls only how strictly the module is enforced at runtime. There is no separate `-fips` image variant.

## Prerequisites

- The operator installed with the Helm chart. For more information, refer to [Installation](../../get-started/installation.mdx#install-the-operator).

## Set the Mode

Set the `global.fipsMode` chart value:

```yaml
global:
  fipsMode: "off"
```

The value sets `GODEBUG=fips140=<mode>` on the operator container and on the `crd-upgrader` pre-install and pre-upgrade hook job. This is a runtime switch, not a build-time one. `GOFIPS140=v1.0.0` always links the FIPS module into the operator image, regardless of `global.fipsMode`.

The valid values are as follows:

| Value | Behavior |
| --- | --- |
| `off` | The default. FIPS mode is disabled at runtime. The module is present in the binary but not engaged, and no self-tests run. |
| `on` | The FIPS module is used, and it runs its startup self-tests. Non-approved algorithms are still allowed. This is the advisory mode. |
| `only` | Non-approved algorithms are rejected. Read [Understand the Limits of only Mode](#understand-the-limits-of-only-mode) before you use this value in production. |

To install or upgrade the operator with a mode, set the value on the command line. The following example sets `only`:

```bash
helm upgrade --install karta oci://ghcr.io/dsx-ai-factory/workload-map/karta \
  -n karta-system --create-namespace --set global.fipsMode=only
```

## Understand the Limits of only Mode

The `only` mode is a testing aid, not a production mode.

According to the [`GODEBUG=fips140` option documentation](https://go.dev/doc/security/fips140#the-fips140-godebug-option), `fips140=only` is a best-effort diagnostic for testing, assessment, and debugging. Upstream Go explicitly does not recommend it for production. When a non-approved cryptographic algorithm is used, the Go FIPS 140-3 module can return an error or panic at the call site, depending on the code path. A panic crashes the pod instead of degrading gracefully. Using `only` is your responsibility. Test it against the actual configuration of your cluster before you rely on it, and do not treat it as a substitute for `on` in production.

### How the Operator Behaves Under only Mode

The crypto usage of the operator was tested under `fips140=only` against a real cluster. The tests covered the TLS connection of client-go to the API server, and the bootstrap of the serving certificate of the webhook (RSA-2048 and `x509.CreateCertificate`, through `open-policy-agent/cert-controller`).

Neither test required disabling the default `X25519MLKEM768` TLS 1.3 hybrid curve with `GODEBUG=tlsmlkem=0`. Some other Go services need this workaround under `fips140=only`, because the implementation of the curve calls a non-approved plain X25519 primitive internally. For more information, refer to [golang/go#78298](https://github.com/golang/go/issues/78298) and [kubernetes/kubernetes#133743](https://github.com/kubernetes/kubernetes/issues/133743).

A future Kubernetes or Go version could change that negotiation. If the operator starts failing outbound TLS handshakes under `fips140=only`, set `tlsmlkem=0` on the operator container as well. That requires a change to `deployment.yaml` in the chart. There is no values-based override today. The `GODEBUG` value is hardcoded from `global.fipsMode`, and `extraArgs` only appends container arguments, not environment variables.

### How the crd-upgrader Job Behaves

The `crd-upgrader` job is a separate case. Its default image, `crdUpgrader.image` with `registry.k8s.io/kubectl`, is a stock `kubectl` build. It is not built with `GOFIPS140`. The setting `GODEBUG=fips140=only` still restricts that binary to approved algorithms at runtime. Without the CMVP-certified module behind the restriction, however, that is not the same as a FIPS 140-3 validated cryptographic implementation.

Whether the TLS handshake of a given `kubectl` build trips the restriction depends on the Go toolchain version that built it. Testing found one build that failed during OpenAPI schema validation, which `tlsmlkem=0` fixed. The risk cannot be ruled out for any given build. When `global.fipsMode` is `only`, the `crd-upgrader` job therefore always sets `GODEBUG=fips140=only,tlsmlkem=0`, not just `fips140=only`.

No FIPS-built `kubectl` image is published upstream today. If the `crd-upgrader` job must run a CMVP-certified module for your compliance requirements, supply your own FIPS-built image with `crdUpgrader.image`.
